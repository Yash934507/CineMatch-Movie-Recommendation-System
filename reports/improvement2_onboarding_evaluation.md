# Improvement 2: Chronological new-user onboarding evaluation

## Objective

Compare SVD fold-in with Bayesian popularity and choose among 3, 5, and 10
onboarding ratings using validation data, then independently measure test performance.
All numbers below are generated by the evaluation script, never manually entered.

## Chronological protocol and leakage prevention

The fixed cutoff is **2005-01-01T00:00:00+00:00** (Unix 1104537600).
A fresh 20-factor, 20-epoch Surprise SVD is trained only on ratings strictly before
that cutoff: **35656 ratings, 272 users,
4395 items**. Its latest training timestamp is
1104519139. The production pickle is neither loaded nor changed.
Popularity counts, means, and its global prior also use only this training frame.
The 20-factor choice and ridge penalties are inherited fixed settings, not retuned
on this experiment. The historical choice of 20 factors used this same MovieLens
snapshot, so complete independence from historical development decisions cannot be claimed.

New users must have their **first-ever observed rating on or after the cutoff**.
Thus no evaluated user's ratings enter the base model, including their onboarding
ratings. Sort their IDs, permute with NumPy seed 42, assign the first
floor(N/2) to validation and the remainder to test. The cohorts contain
169 and 169
users respectively, before per-size eligibility filtering. Every eligible user
in each cohort is evaluated; there is no further user subsampling.

For each N, sort by timestamp ascending then movieId ascending, use exactly the
first N ratings, and test only ratings whose timestamp is **strictly greater**
than the Nth timestamp. Unselected ratings tied at that boundary are excluded
from both profile and test. There is no reliable ordering within a tied timestamp.

## Eligibility

- At least N+1 observed distinct movies; duplicate user/movie rows are rejected.
- Every one of the actual first N movies must have base-model factors. We exclude
  the user-size pair otherwise; we do not skip unknown early movies to find replacements.
- At least one strictly later movie rated >=4.0. All strictly later ratings,
  including ratings below 4.0 and unknown items, remain in the test period.
- Ratings must be finite and within 0.5-5.0. Input data is validated before splitting.

## Shared scoring mathematics

Both API and evaluation import [onboarding.py](../src/cinematch/onboarding.py).
Given fixed item factors q_i and biases b_i, let X have rows [1, q_i], and
y_i = r_i - global_mean - b_i. Solve
`(X.T X + diag(0.02, 0.1, ..., 0.1)) c = X.T y` for the temporary user bias
and factors. Predict `global_mean + user_bias + item_bias + dot(user, item)`
and clip to [0.5, 5.0]. Only onboarding ratings enter this solve.

Popularity reuses the existing prior-weighted method:
`(count * movie_mean + 50 * training_global_mean) / (count + 50)`.
Its ties use descending training count then ascending movieId; fold-in ties use
ascending movieId, preserving the API's existing behavior.
Unknown test items have zero item bias/factors for fold-in (global mean + user bias)
and training global mean for popularity. They are never silently dropped.

## Identical candidate sets

Each user-size candidate set contains **all strictly later test movies**, plus
100 uniformly sampled movies without replacement from the training item catalog
that occur nowhere in that user's complete observed history. If fewer than 100
are available, use all available. SeedSequence([42, userId]) seeds each user;
negative samples remain identical across N. The sorted candidate list is computed
once and passed to both strategies. Every onboarding movie is excluded.
Full history is used only for evaluation negative exclusion, never model fitting.
The detail CSV records candidate IDs, SHA-256, onboarding IDs, relevant IDs,
boundary timestamps, unknown test counts, actual negative count, and Top-10 IDs.

## Metric definitions

At K=10, Precision = relevant recommendations / 10 (even if fewer are returned);
Recall = relevant recommendations / all relevant later movies; Hit Rate = 1 if
any top-10 movie is relevant, otherwise 0. Binary DCG sums relevance/log2(rank+1)
with ranks starting at 1; NDCG divides by the ideal DCG for min(10, relevant count).
Report equal-weight means over users. Coverage is the number of unique recommended
top-10 movie IDs divided by the complete metadata catalog (9742 movies),
calculated separately for each strategy, size, and cohort.

## Product decision (locked before test scoring)

Use common validation users eligible at all three sizes (78)
to reduce cohort-selection bias. The predeclared primary metric is mean NDCG@10.
Choose the smallest size within 0.01 absolute NDCG of the best fold-in size.
Then bootstrap paired fold-in minus popularity differences over those users
(2,000 resamples, seed 42); change the current minimum only if the percentile
95% interval is entirely positive. If it overlaps zero, retain the current
three-rating flow provisionally. If entirely negative, recommend popularity
as the default and keep fold-in experimental. Test results never enter this rule.

Validation best size: **3**; near-best preferred size:
**3**; selected minimum: **3**.
Paired NDCG difference: -0.05697; interval:
[-0.08912, -0.02661].
Recommend fold-in as the default: **False**. Keep popularity fallback: **True**.
Evidence favors popularity; fold-in should remain experimental.

The compatibility-preserving implementation keeps the existing POST endpoint and
React flow operational with three ratings. This experiment does not silently
switch that endpoint to popularity while claiming `svd-fold-in` in its response.
Fold-in remains available as an experimental option; the evidence recommends
popularity for default recommendations. No React minimum change is warranted.

## Limitations

- This is a fixed historical model evaluated on new users over a long later period,
  not a continuously updated production simulation. Catalog and preference drift
  can be large. A single cutoff and seed are not a robustness study.
- Requiring known early items favors users onboarding with older movies. Excluded
  users and cold-item onboarding require separate evaluation.
- Later unknown movies are included as requested, even when they may not have
  existed at onboarding time. This is retrospective ranking, not an availability-aware
  serving replay. Their neutral scores may rank highly for some profiles.
- Unrated sampled negatives are unobserved preferences, not confirmed dislikes.
  Sampled metrics do not equal whole-catalog ranking metrics.
- MovieLens timestamps describe rating activity, not necessarily viewing order;
  batch ratings and ties weaken the interpretation of an onboarding sequence.
- Even the common-user validation comparison has changing horizons and relevant
  sets as N increases. The 0.01 tolerance is a product-friction heuristic; the
  bootstrap interval is exploratory and not corrected for selection across N.
- Model capacity is fixed from prior work on the same dataset; no new test-based
  tuning is performed, but this is not an untouched external benchmark.
- Offline metrics do not establish real-user satisfaction, diversity, or completion
  rates. Confirm any provisional decision with prospective users before rollout.
